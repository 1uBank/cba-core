# 1UBank patch list

Every change we make to an **existing Apache Fineract file** is recorded here. New files and modules we add do not need an entry.

Before upgrading to a new Fineract release, check each entry: has it been fixed upstream (drop our patch), or does it still need to be applied?

| # | Date | Upstream file(s) changed | Why | Our commit / PR | Upstream issue / PR | Status |
|---|---|---|---|---|---|---|
| 1 | 2026-11-08 | `fineract-provider/src/main/resources/application.properties` | Lists the `oneubank.auth-sync.*` settings (staff sync and first-login migration) with their environment variables and defaults, so they are visible next to Fineract's own settings. Adds lines only | | | `ours only` |
| 2 | 2026-11-17 | `fineract-provider/.../security/config/OidcFederationSecurityConfig.java` | With OIDC federation on, the application did not start: the converter's `@Bean` method needed the configuration instance, which needed the converter. The method is now static | PR #9 | | `ours only` |
| 3 | 2026-11-18 | `fineract-provider/.../security/config/OidcFederationSecurityConfig.java` | The OIDC chain's `"/api/**"` string pattern became a Spring MVC matcher, which drops the Jersey servlet's `/api` prefix, so it never matched and every call went to the Basic chain. It now uses the same path matcher as `SecurityConfig`. With Basic Auth on it takes only API calls with a Bearer token (Spring Security refuses two chains with the same matcher); with Basic Auth off it takes every API call, and registers the method security and password encoder that `SecurityConfig` would have | | | `ours only` |
| 4 | 2026-11-18 | `fineract-provider/.../core/config/SecurityValidationConfig.java` | Fineract refused to start unless Basic Auth or its own OAuth2 server was on. OIDC federation now counts as a sign-in scheme, so it can run alone | | | `ours only` |
| 5 | 2026-11-18 | `fineract-security/.../security/api/UserDetailsApiResource.java` | `GET /v1/userdetails` (the signed-in user's office, roles and permissions, which the portal loads after sign-in) was loaded only with Fineract's own OAuth2 server. It now also loads with OIDC federation, whose tokens are the same `FineractJwtAuthenticationToken` | | | `ours only` |
| 6 | 2026-11-18 | `fineract-provider/.../security/config/OidcFederationSecurityConfig.java` | `OidcTenantAwareFilter`, a `@Bean`, was also registered as a servlet filter, which cleared the tenant before `IdempotencyStoreFilter` saved the command result: with OIDC federation on, every write failed (`m_portfolio_command_source` does not exist). Its servlet registration is now disabled | | | `ours only` |
| 7 | 2026-11-23 | `fineract-savings/.../savings/domain/SavingsProduct.java`, `SavingsProductAssembler.java`, `savings/data/SavingsProductDataValidator.java`, `fineract-core/.../savings/data/SavingsProductData.java`, `fineract-provider/.../savings/service/SavingsProductReadPlatformServiceImpl.java`, `SavingsProductWritePlatformServiceJpaRepositoryImpl.java` | Two fields on savings products, `nubanPrefix` and `enforceTierLimits` (columns added by `0006_oneubank_savings_product_numbering.xml`), accepted by the product create/update calls and returned by the product reads. A prefix change on a product that has accounts is refused with `error.msg.savingsproduct.nuban.prefix.locked` | | | `ours only` |
| 8 | 2026-11-23 | `fineract-provider/.../account/service/AccountNumberGenerator.java` and its test `AccountNumberGeneratorTest.java` | Savings accounts on a product with a NUBAN prefix are numbered as NUBANs by `NubanGenerator` (prefix, 6-digit serial, CBN check digit) instead of Fineract's padded ID | | | `ours only` |
